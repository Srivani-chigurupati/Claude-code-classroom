Task 4.1: Implement Retry Logic
Complete the withRetry function that implements exponential backoff.

Algorithm:

Try to execute the function
If it succeeds, return the result
If it fails and retries remain:
Calculate backoff delay: delayMs * 2^(attempt - 1)
Add jitter (random 0-100ms) to prevent thundering herd
Wait for the calculated duration
Retry
If all retries exhausted, throw ReviewError with RETRY_EXHAUSTED code

Deliverable: Rate Limiter
File to complete: src/utils/rate-limiter.ts

The rate limiter prevents API throttling using a token bucket algorithm with sliding window.

Understanding the Sliding Window
The sliding window tracks requests made in the last 60 seconds:

At any moment, only count requests from the past 60 seconds
As time passes, old requests "fall off" the window
This provides smooth rate limiting vs. fixed time buckets

Methods to implement:

pruneOldRecords() - Start here, it's the simplest

Filter requestHistory to keep only records from the last 60 seconds

canProceed(estimatedTokens) - Check if request can proceed immediately

Call pruneOldRecords() first
Check three conditions: concurrent requests, requests per minute, tokens per minute
Return true only if all conditions are met
waitForSlot() - Wait for a concurrent request slot

Create a Promise and add its resolve function to waitQueue
The resolve will be called later by release()
waitForRateLimit(estimatedTokens) - Wait until rate limits allow the request

Loop while canProceed() returns false
Calculate wait time based on when the oldest request expires
Sleep and check again
acquire(estimatedTokens) - Main entry point

Wait for concurrent slot (use waitForSlot())
Wait for rate limit (use waitForRateLimit())
Increment activeRequests
Add record to requestHistory

Troubleshooting
Rate limiter not preventing errors
Symptom: Still getting rate limit errors from API

Common Causes:

Rate limiter not integrated with orchestrator
acquire() not called before API requests
release() not called after requests complete
Limits set too high for your API tier
Solution: Integrate rate limiter by wrapping your orchestrator's query calls:

await rateLimiter.acquire(estimatedTokens);
try {
  const result = await orchestrator.reviewPullRequest(...);
  return result;
} finally {
  rateLimiter.release();
}
